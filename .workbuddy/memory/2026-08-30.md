## 已完成：ArchUnit 结构化测试（Harness Pillar 2 落地）

**交付物**
- 父 POM `<dependencies>`：新增 `spring-boot-starter-test` + `archunit-junit5:1.3.0`（test scope）
- 父 POM `<build><plugins>`：锁定 `maven-surefire-plugin:2.22.2`（关键，见踩坑）
- `ruoyi-admin/src/test/java/com/ruoyi/architecture/ArchitectureRulesTest.java`（11 规则 + 1 自检）
- `ruoyi-admin/src/test/java/com/ruoyi/architecture/MapperXmlRulesTest.java`（3 规则）
- `.harness/enforcement.yml`（机器可读规则声明，YAML 已校验）

**实测结果**：`mvn clean test` → Tests run: 15, Failures: 0 → BUILD SUCCESS

**踩坑 1（重要）：Surefire 版本**
本项目父 POM **不是** `spring-boot-starter-parent`，Maven 默认 Surefire 是 **2.12.4**，
**不识别 JUnit 5**，会导致 `mvn test` 构建成功但**静默跑 0 个用例**。必须显式锁定 ≥2.22.0。

**踩坑 2：ArchUnit API 记错**
- `slices()` 在 `com.tngtech.archunit.library.dependencies.SlicesRuleDefinition`，**不在** `ArchRuleDefinition`
- `JavaClasses` 的方法是 `contain(Class<?>)`，不是 `containType(...)`
- 排查方法：`javap -cp <Windows路径jar> <类名>`（javap 是 Windows 程序，必须用 `C:/` 路径，
  用 Git Bash 的 `/c/` 路径会报"找不到类"）

**踩坑 3：Javadoc 里的 `*/`**
在 Javadoc 注释中写 `classpath*:mapper/**/*Mapper.xml`，其中的 `*/` 会**提前终结注释**导致编译失败。
注释里避免出现 `/**/` 字面量。

**踩坑 4：规则作用域**
首版规则全量应用时，框架原生代码触发告警（`ruoyi-generator` 的 `GenController`、
`ruoyi-framework` 的 `UserDetailsServiceImpl`、`ruoyi-generator` 的 `GenTableServiceImpl`）。
这些我们不改 → 规则收窄到 `com.ruoyi.biz`，并在 Controller 规则里加白名单。
**经验：一条会在"我们不打算改的代码"上失败的规则，是不可执行的噪音。**

**反向验证（必做）**
临时注入无 `@PreAuthorize` 的 Controller，规则成功拦截并精确定位到
`TempUnsecuredController.leak()` 第 21 行。验证后已清理。
**教训：ArchUnit 全绿 ≠ 规则有效，必须做反向验证，否则可能是空跑通过。**

**环境**：Git Bash 下 `mvn` 报 `找不到主类 org.codehaus.plexus.classworlds.launcher.Launcher`
（路径转换 bug），改用 **`mvn.cmd`**。Maven 3.9.16 + JDK 1.8.0_271。
多模块必须加 `-am`，否则报 `Could not find artifact com.ruoyi:ruoyi-framework`。

testing.md §1.1 与 §3 更新现状（架构测试已有，业务测试仍为 0）；

**依赖改动**
- 父 POM：加 `h2`（test scope）
- ruoyi-system POM：加 `mybatis-spring-boot-starter-test:2.3.1`（与 pagehelper 传递引入版本对齐）
- 父 POM properties：加 `mybatis.boot.version`

**踩坑 1：`@MybatisTest` 报 Unable to find a @SpringBootConfiguration**
`@MybatisTest` 从测试类所在包向上找 `@SpringBootConfiguration`。
`RuoYiApplication` 在 **ruoyi-admin**，ruoyi-system 测试 classpath 上没有 → 必须自建
`TestMybatisApplication`（在 `com.ruoyi` 包）。
**用 `@SpringBootConfiguration` + `@EnableAutoConfiguration`，不要用 `@SpringBootApplication`**
（后者触发 @ComponentScan，就不是切片测试了）。

**踩坑 2：Mapper 接口无 `@Mapper` 注解**
RuoYi 靠 ruoyi-framework 的 `MyBatisConfig` 里 `@MapperScan` 扫描，
但 ruoyi-system 测试不加载 framework → 必须在测试配置类上补 `@MapperScan("com.ruoyi.**.mapper")`。

**踩坑 3：ruoyi-system 编译期没有 MyBatis**
MyBatis 经 ruoyi-common 的 pagehelper 传递引入，最终在 ruoyi-admin 装配。
ruoyi-system 测试要跑 @MybatisTest 需显式加 starter-test 依赖。

**设计决策：用 @Disabled 固化已知缺陷**
两个用例标记 `@Disabled` 而非删除/跳过理由：
- `SysProductServiceImplTest.deleteSysProductByProductIds_hasChildren_...`（P1-2 孤儿数据）
- `SysProductMapperTest.selectSysProductList_byParentId_shouldFilter`（P1-2 前置：XML where 不支持 parent_id）
修复后移除注解即转为通过 → 缺陷有了自动化验收标准，不会在文档里被遗忘。

**H2 注意事项**：schema.sql 去掉 `ENGINE=InnoDB` / 内联 `COMMENT` 等 MySQL 专有语法；
data.sql 主键从 100 起，避免与 H2 自增主键（从 1 开始）冲突。

**测试自带鉴别力设计**：无条件查 3 条 / 按名称查 1 条——若 where 失效会返回 3 条而失败，
无需额外反向验证。
